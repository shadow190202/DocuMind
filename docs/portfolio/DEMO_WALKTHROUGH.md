# DocuMind — Live Demonstration Walkthrough Script

This script provides a practical, step-by-step demonstration sequence showing DocuMind's live application flows. It is formatted for technical interviews, product demonstrations, recruiter evaluations, and video walkthroughs.

---

## Prerequisites for Live Demonstration
* Application running locally (`npm run dev`) or in Docker (`docker run`).
* Web browser opened to `http://localhost:3000` (or your production domain).
* Two sample documents prepared (e.g. `financial_report.pdf` and `quarterly_metrics.csv`).

---

## Scenario 1: Public Landing Page & Authentication Gate

1. **Navigate to Root:** Open `http://localhost:3000/`.
2. **Observe:** The public landing page renders the DocuMind branding, hero banner, feature highlights (semantic search, page-level citations, multi-format support), and call-to-action buttons (*"Get Started"*, *"Sign In"*).
3. **Route Protection Test:** In an incognito window, attempt to navigate directly to `/dashboard`.
   * *Expected Behavior:* Next.js middleware intercepts the unauthenticated request and immediately redirects to `/sign-in`.
4. **Sign In:** Log in using a standard Clerk user account.
   * *Expected Behavior:* Session cookie is established, and user is redirected to `/dashboard`.

---

## Scenario 2: Main Dashboard & Document Vault

1. **Dashboard Overview:** Navigate to `/dashboard`.
2. **Observe:** The dashboard displays quick navigation links, document counters, and recent activity.
3. **Navigate to Documents:** Click **"Documents"** in the navigation header to open `/documents`.
4. **Observe Vault:** Displays the document table with columns for filename, format badge (`PDF`, `DOCX`, `TXT`, `CSV`), file size, processing status, and action buttons.

---

## Scenario 3: Secure Document Ingestion (20 MB Guard & Magic Bytes)

1. **Navigate to Upload:** Click **"Upload Document"** or navigate to `/documents/upload`.
2. **Drag and Drop File:** Select a sample PDF file (<20 MB) and initiate upload.
3. **Observe Ingestion Feedback:**
   * Progress bar indicates upload completion.
   * Deep magic-byte validation verifies `%PDF-` header.
   * Document record is created in PostgreSQL with status `pending`.
4. **Trigger Processing:** On the document listing or detail view, click **"Process Document"**.
   * Status transitions: `pending` -> `processing` -> `completed`.
   * Physical page numbers are extracted, hierarchical chunks (~1000 chars) are created, and 768-dimensional embeddings are stored in `document_chunks`.

---

## Scenario 4: Document Details & Chunk Inspection

1. **Open Document Details:** Click on the processed document title to navigate to `/documents/[id]`.
2. **Observe Tabs:**
   * **Overview:** Displays filename, MIME type, file size, status, and creation date.
   * **Extracted Text:** Renders the clean text extracted from the file.
   * **Chunks & Embeddings:** Renders the partitioned chunks with sequential `chunk_index`, physical page number badge, character length, and confirmed `vector(768)` embedding status.

---

## Scenario 5: Scoped & Cross-Vault Semantic Vector Search

1. **Scoped Search (Document View):** In `/documents/[id]`, enter a conceptual keyword into the document search bar (e.g., *"revenue growth"*).
   * *Observe:* Returns matching chunks from that document sorted by cosine similarity score (`1 - (embedding <=> query)`).
2. **Cross-Vault Search:** Click the global search bar in the main navigation.
   * *Observe:* Queries all documents owned by or shared with the user, returning ranked chunk passages with page numbers and document title badges.

---

## Scenario 6: Grounded RAG Chat with Verifiable Page Citations

1. **Navigate to Chat:** Click **"Chat"** in the navigation bar to open `/chat`.
2. **Select Target Document:** Pick the processed PDF from the document dropdown selector.
3. **Submit Query:** Ask a specific question answered by the document (e.g., *"What were the operating expenses in Q3?"*).
4. **Observe Response:**
   * Grounded answer is generated by `gemini-3.8-flash`.
   * **Citation Panel:** Renders verified citation cards below the answer displaying the exact passage snippet, chunk index, and physical **Page Number**.
   * **Token Counter:** Displays the prompt and completion tokens consumed for the query.
5. **Multi-Turn Continuity:** Ask a follow-up question (e.g., *"How does that compare to Q2?"*).
   * Conversation session title updates dynamically and dialogue history persists.
6. **Export Conversation:** Click **"Export"** and select **Markdown** to download the full transcript with citations.

---

## Scenario 7: Executive Document Summarization

1. **Open Document Detail View:** Navigate to `/documents/[id]`.
2. **Request Summary:** Click **"Generate Summary"** and select **"Executive Summary"**.
3. **Observe Output:**
   * Structured executive summary text renders along with bulleted key takeaways.
   * The result is cached in the `document_summaries` table.
4. **Cache Verification:** Refresh the page and request the summary again.
   * *Observe:* The summary loads instantly from the cache with zero delay and zero additional API calls.

---

## Scenario 8: Side-by-Side Multi-Document Comparison

1. **Navigate to Compare:** Click **"Compare"** in the navigation header to open `/compare`.
2. **Select Pair:** In the dual-document picker, select two distinct uploaded documents.
3. **Run Comparison:** Click **"Analyze Differences"**.
4. **Observe Output:**
   * Side-by-side comparative analysis renders in structured markdown.
   * Structured JSON highlights shared similarities, key differences, and actionable recommendations.
   * Results are cached in `document_comparisons`.

---

## Scenario 9: Collaborator Document Sharing & Granular Permissions

1. **Open Document Permissions:** On `/documents/[id]`, click **"Share"**.
2. **Grant Collaborator Access:** Enter a registered collaborator's email and select **"Read"** permission.
3. **Collaborator Verification:**
   * Log in as the collaborator in a separate browser profile.
   * The shared document appears in the collaborator's document list.
   * Collaborator can view text, search chunks, and ask chat questions.
   * Collaborator cannot delete the document or modify sharing permissions.
4. **Permission Revocation:** Switch back to the owner account and click **"Revoke"** on the collaborator entry.
   * Collaborator access is immediately revoked; subsequent requests return HTTP 404.

---

## Scenario 10: Authoritative Admin Dashboard & System Diagnostics

1. **Promote Admin Account (One-Time Setup):**
   ```bash
   node scripts/bootstrap-admin.mjs <your-admin-email>
   ```
2. **Access Admin Portal:** Navigate to `/admin/dashboard`.
3. **Observe Admin Features:**
   * **KPIs Overview:** Platform-wide metrics for total users, documents, queries, and token consumption.
   * **User Directory (`/admin/users`):** Displays paginated user accounts with upload counts and token usage. Test role modification with concurrency-safe last-admin protection.
   * **Processing Monitor (`/admin/processing`):** Real-time queue health and error tracking.
   * **AI Usage Telemetry (`/admin/usage`):** Platform-wide token distribution charts by model (`gemini-3.8-flash` vs `gemini-embedding-001`).
   * **System Health (`/admin/system`):** Displays live PostgreSQL ping latency, active `pgvector` extension version, total disk storage utilization, and table row counts across all 9 application tables.
