# DocuMind — System Specification & Technical Architecture

## 1. Overview
DocuMind is an AI-powered document intelligence platform that allows users to upload documents (PDF, DOCX, TXT, CSV), extract structured text with page attribution, generate 768-dimensional vector embeddings, perform semantic vector search via PostgreSQL `pgvector`, and engage in grounded RAG (Retrieval-Augmented Generation) chat with verifiable page citations.

## 2. Core Capabilities
- **Multi-Format Ingestion:** Automated text extraction for PDF, DOCX, TXT, and CSV up to 20 MB with magic-byte validation.
- **Accurate Page Citations:** PDF extraction retains physical page boundaries, mapping chunks to exact pages for transparent source citations (`[SOURCE N]`).
- **Semantic Vector Search:** 768-dimensional chunk embeddings indexed in PostgreSQL with `pgvector` cosine similarity.
- **Grounded Q&A:** Gemini 3.8 Flash RAG engine with prompt-injection defense, strict source fences, and citation generation.
- **Document Summarization:** Dual-mode summarization (single-pass for <= 12 chunks, map-reduce for large documents) across executive, key points, dates, numbers, and action items.
- **Document Comparison:** Side-by-side comparative analysis highlighting additions, omissions, alterations, and numerical/date changes.
- **Granular Permissions & Sharing:** Multi-tenant isolation with read, write, and owner roles, uniform 404s for unauthorized resource probing.
- **Admin Governance & Telemetry:** Server-side PostgreSQL-authoritative role verification, user directory management, and real-time token telemetry.

## 3. Technology Stack
- **Framework:** Next.js 14 App Router, React 18, Tailwind CSS
- **Database & ORM:** PostgreSQL with `pgvector`, Drizzle ORM
- **Authentication:** Clerk (`@clerk/nextjs`) with database-authoritative role enforcement
- **AI Models:** Google Gemini (`@google/genai`)
  - Embeddings: `gemini-embedding-001` (768-dim)
  - Chat & Analysis: `gemini-3.8-flash`
- **Parsers:** `pdf-parse`, `mammoth` (DOCX), `csv-parse`
- **Validation:** Zod schemas
- **Storage:** Pluggable local filesystem storage (`/storage`) or Vercel Blob

## 4. User Roles & Security
- **Normal User:** Upload, search, chat, summarize, compare, and manage own documents. Share documents with explicit permissions.
- **Administrator:** Authoritative `users.role === 'admin'` checked in PostgreSQL. Access to `/admin` dashboard, processing queue monitoring, user directory, and platform telemetry.
- **Security Invariants:**
  - Strict tenant isolation: All vector searches and database queries are scoped by authenticated user ID or explicit permission grant.
  - Path traversal containment: `safeResolvePath` enforces canonical boundary resolution and rejects traversal attempts or symlink escapes.
  - Rate limiting: Sliding-window limiter on sensitive endpoints to protect upstream quotas.
  - Centralized error masking: Production errors masked with unique correlation IDs (`x-correlation-id`).

## 5. Database Schema
- `users`: User profiles, email, role (`user` | `admin`), timestamp metadata.
- `documents`: Document records, file metadata, processing status (`pending`, `processing`, `completed`, `failed`), storage URL, retention timestamp.
- `document_chunks`: Document text segments, 768-dim vector embeddings, chunk index, page number, token estimates.
- `conversations`: Chat sessions scoped to specific documents or entire document vaults.
- `messages`: Conversational dialogue turns with prompt token counts, completion token counts, and retrieved chunk references.
- `document_permissions`: Granular sharing records (`read`, `write`, `admin`).
- `document_summaries`: Cached multi-dimension summaries (`executive`, `detailed`, `key_points`, `dates`, `numbers`, `action_items`, `comprehensive`).
- `document_comparisons`: Cached comparative analyses between base and target documents.
- `ai_usage_logs`: Real-time token consumption logs and model telemetry.
